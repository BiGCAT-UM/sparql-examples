# WikiPathways examples

`examples/WikiPathways/` holds every public example query for the WikiPathways SPARQL endpoint:
the SNORQL example queries from [wikipathways/SPARQLQueries](https://github.com/wikipathways/SPARQLQueries)
and the queries on the WikiPathways website ([sparql](https://www.wikipathways.org/sparql.html),
[federated](https://www.wikipathways.org/federated.html), [metabolome](https://www.wikipathways.org/metabolome.html)).

`sources.tsv` says where each example comes from and keeps its number, and so its IRI, stable:

| kind     | meaning |
|----------|---------|
| `rq`     | generated by `rq2ttl.py` from the `.rq` file in `source`; do not edit the `.ttl` by hand |
| `manual` | written by hand in this repository |
| `web`    | written by hand from a query on the WikiPathways website (`source`, block number in `note`) |
| `same`   | `source` is the same query as example `id`, possibly with another constant; no file of its own |
| `skip`   | `source` is not published here; `note` says why |

Numbers are never reused. When a source disappears, its example stays.

## Updating after a change in SPARQLQueries

```bash
git clone https://github.com/wikipathways/SPARQLQueries ../SPARQLQueries   # or pull
pip install rdflib
python scripts/wikipathways/rq2ttl.py --source ../SPARQLQueries
```

New `.rq` files get the next free number and are added to `sources.tsv`. Parameterised SNORQL
queries (`# param:` headers, `{{name}}` placeholders) are written with their default values, so
every example runs as it is. `--check` writes nothing and exits with 1 if anything would change.

Fix query syntax in SPARQLQueries itself, not in the generated files: they are overwritten on the next run.

## Versions

An example IRI always stands for the current version of the query. Each generated example also
records which version of the SNORQL query it was made from: `dcterms:source` links to the `.rq`
file at the commit that last changed it, and `dcterms:modified` gives that commit's date. The
generator therefore refuses `.rq` files with uncommitted changes and commits that are not on
SPARQLQueries' `master` yet (`--allow-unmerged` to try out a branch). Merge pull requests there
with a merge commit, not a squash, or the recorded commits disappear from `master`.
